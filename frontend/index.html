Software Engineering All Units (I to V) — Complete Mapping Scenario 4 • Reg No: 34

UNIT I — Software Process Model & Project Scheduling

Process Model: Incremental & Iterative Agile-Scrum Model. Delivered in 5 incremental builds: SRS & 3NF Database → Catalog & Member CRUD → Manual Date Issue/Return & Fine Engine → Date-by-Date Graphs & Python FDS Analytics → Verification & Deployment.

UNIT II — Requirements Engineering (IEEE 830 SRS — All 8 Requirements)

  • FR-1: Maintain book, author, category, and student membership details in MySQL.
  • FR-2 & FR-3: Issue and return books while blocking loans when available_copies == 0.
  • FR-4 & FR-5: Record manual Issue Date, Due Date, and Return Date; compute overdue fine at Rs. 5/day and set status to RETURNED.
  • FR-6, FR-7 & FR-8: Generate reports, feed Python FDS analytics, and visualize borrowing patterns by date, category, and book.

UNIT III — System Architecture, UML & 3NF Database Design

Three-tier REST architecture: HTML/JS/Chart.js Frontend (:3000) ↔ Java HTTP REST API (:8080) ↔ 3NF Normalized MySQL Database (categories, authors, books, members, transactions).

UNIT IV — Software Testing (Black-Box, White-Box & Boundary Cases)

Tested: (1) Adding a new book increments Total Books KPI & MySQL count; (2) Issuing a book updates the daily activity chart on the selected date; (3) Issuing a 0-copy book triggers HTTP 409 Conflict; (4) Returning a book with a manual return date computes exact overdue fine and switches status to RETURNED.

UNIT V — Software Maintenance, Configuration & Risk Management

Versioned modular folders (backend/, database/, frontend/, python_fds_analytics/, software_engineering_all_units/) with MySQL JDBC + automatic CSV fallback so the app remains 100% functional during offline or live demos.
